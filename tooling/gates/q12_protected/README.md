# Q-12 «Эталоны и правила» (guard-гейт)

**Критерий:** `QUALITY_GATES.md` Q-12 · **TASK:** §3.3 · **Сценарии:** Б-9, Б-11, Б-12

## Назначение
Защищённые пути (golden/snapshot-эталоны, тесты, тарифы): метки `rule-change` /
`test-change` ставит гейт по дифу (не автор); любое касание — второй проверяющий;
новый эталон-оракул в одном PR с изменением кода — усиленное ревью (Б-11); файл
под несколькими guard-гейтами — обе метки и наивысший подписант (Б-12).

## Конфиг
| Ключ | Смысл |
|---|---|
| `protected_paths` | список `{glob, label, category, oracle}` — охраняемые пути; `oracle: true` включает проверку Б-11 |
| `code_globs` | какие пути считаются кодом (для Б-11) |
| `q11_config_globs` | пересечение с Q-11 → `gates-change` + наивысший подписант (Б-12) |

## Коды findings
`PROTECTED_PATH_TOUCHED` (info) · `GOLDEN_ORACLE_WITH_CODE` (warning) ·
`OVERLAP_HIGHEST_SIGNER` (info).

## Ограничения
- Семантические сигналы (изменение числовых литералов в расчётных модулях) —
  рекомендация К1, выполняется вторым ревьюером, не этим гейтом.
- Ослабление — никак, кроме E-D (`EXCEPTIONS_POLICY.md`).
