# L0-детектор «Периметр репозитория» (ночной/админ-гейт)

**Критерий:** `QUALITY_GATES.md` §1.5 · **TASK:** C-4 · **Режим:** fail-closed

## Назначение
Проверяет, что принуждение нельзя выключить изнутри репозитория:
1. защита основной ветки: прямой push запрещён, обязательные проверки заданы,
   force-push и удаление ветки запрещены;
2. CODEOWNERS существует и покрывает инфраструктуру стандарта (workflows,
   конфиги линтеров, `EXCEPTIONS.md`, `REPO_CLASS`, baseline, `AGENTS.md`,
   PR-шаблон, сам CODEOWNERS);
3. одобрения PR — только люди (логины ИИ-агентов по паттернам — ошибка);
4. обход админа — либо запрещён (`enforce_admins`), либо оформлен как
   процессное отступление (warning).

## Входы
Через Adapter API: настройки защиты ветки, текст CODEOWNERS, логины ревьюеров.
Config: `branch` (main), `infra_paths` (список §1.5.2), `agent_login_patterns`,
`pr` (номер PR для проверки ревьюеров; 0 — пропуск этого подчекa).

## Коды findings
`BRANCH_NOT_PROTECTED` · `NO_REQUIRED_CHECKS` · `FORCE_PUSH_ALLOWED` ·
`BRANCH_DELETION_ALLOWED` · `ADMIN_BYPASS_NOT_ENFORCED` (warning) ·
`CODEOWNERS_MISSING` · `CODEOWNERS_EMPTY` · `CODEOWNERS_NO_INFRA_COVERAGE` ·
`AGENT_APPROVAL_DETECTED`.

## Fail-closed
Недоступность API или данных о защите → `UNAVAILABLE` (красный, exit 3),
никогда не «молчаливый OK».

## Важные ограничения (честно)
- GitHub отдаёт настройки защиты **только админам**: токен в джобе должен иметь
  права администратора; без них API возвращает 404 — гейт сообщит «ветка не
  защищена», что для неточного токена ложно-положительно. Поэтому гейт —
  ночной/админский, не PR-джоба.
- **Видимость репозитория (решение владельца, 2026-11-17):** приватные
  репозитории на GitHub Free не поддерживают branch protection — проект,
  работающий по стандарту, обязан быть публичным **или** на тарифе Pro/Team+
  (условие внедрения, как и весь L0 §1.5: без периметра стандарт не внедрён).
