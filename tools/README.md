# tools/ — служебные скрипты репозитория

## doc_consistency.py

Механизм консистентности собственных документов (**ROADMAP A-3**). Источники находок:
GE-9 («дублирование между документами дрейфует»), OP-22 («дублирование чек-листов») —
см. `standards/review/REVIEWS_STATUS.md`; урок «G3 vs G-08» — расхождение перекрёстных
ссылок в v1.0.

- **Вход:** все `*.md` репозитория.
- **Выход:** текстовый отчёт (или `--json` — машиночитаемый); код возврата 0/1.
- **Запуск:** `python tools/doc_consistency.py [--json]` (Python 3.11+, только stdlib).
- **CI:** `.github/workflows/consistency.yml` — на каждый push в `main` и на PR (fail на PR — критерий A-3).

**Проверки:** `LINKS`, `FILES`, `SECTIONS`, `GATES` (каталог Q-xx, непрерывность, запрет G-xx), `PRINCIPLES`, `SCENARIOS`, `TASKS`, `STAGES`, `VERSIONS`, `TERMS`, `CLAIMS`, `SEQ`. Полные описания — в докстринге скрипта.

**Допущения и границы:**

- архив ревью (`standards/review/review_*.md`) проверяется только на битые ссылки:
  исторические идентификаторы (G-xx, счётчики v1.0) и цитаты там легитимны;
- `REVIEWS_STATUS.md` исключён из `GATES`/`CLAIMS` — документ цитирует находки до v1.1;
- `user/…` — локальный архив владельца (вне репозитория), упоминания пропускаются;
- ссылка «§N» без имени документа в строке считается ссылкой на текущий документ
  (ядро и guidelines); для README/ROADMAP/REVIEWS_STATUS такие ссылки пропускаются
  как неоднозначные; если в строке поименованы документы — §N проверяется против
  любого из кандидатов (снимает неоднозначность «§5 и таблица X.md»);
- якорные ссылки `#…` и внешние URL не проверяются.

**Ограничение:** механика ловит ссылки, идентификаторы, количества, структуру и
переопределения терминов — но не смысловой дрейф перефразированных фрагментов.
Смысловая консистентность остаётся зоной ревью (`QUALITY_GATES.md` §5: «механически
проверяемое vs требующее суждения»).

**Куда это растёт:** при создании companion-репозитория (`standards-tooling`,
трек C) тот же подход переиспользуется в гейте Q-19 (сверка якорей с реестром) —
здесь скрипт служит рабочим прототипом «checker против источников истины».
